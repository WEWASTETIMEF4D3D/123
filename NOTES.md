# NOTES — вариант V=1 (расписание секций), N=8

## Почему на DELETE возвращается 204, а не 200?
204 = «операция найс, тела нет». После удаления возвращать нечего. 200 подразумевает тело ответа.

## Что произойдёт с данными при перезапуске сервера и почему так работает массив в памяти?
Обнулятся. Массив lessons живёт в памяти процесса Node.js; на диск ничего не пишется. После старта seed() заново создаёт 8 записей.

## Зачем нупжен вызов next(err) и что сломается, если его убрать?
Передаёт ошибку в Express → вызывает централизованный errorHandler. Без него ответ не отправится: запрос зависнет до таймаута, ошибка проглотится.

## Как реализовано персональное правило (нет пересечений по времени в один день)?
Файл `src/services/lessonService.js`:

В lessonService.js функция assertNoOverlap: проверяет, что при одинаковом weekday начало каждого интервала раньше конца другого. «Встык» (12:00–12:00) не считается пересечением. ignoreId нужен, чтобы при PUT/PATCH занятие не конфликтовало само с собой. Вызывается в create, replace, update.

```js
function assertNoOverlap(lesson, ignoreId) {
  const conflict = store.find(
    (l) =>
      l.id !== ignoreId &&
      l.weekday === lesson.weekday &&
      lesson.startTime < l.endTime &&
      l.startTime < lesson.endTime
  );
  if (conflict) {
    throw new HttpError(400, `Занятие пересекается с "${conflict.title}" ...`);
  }
}
```

Два интервала пересекаются, если начало каждого раньше конца другого. Занятия «встык»
(один заканчивается в 12:00, другой начинается в 12:00) пересечением не считаются.
`ignoreId` нужен, чтобы при PUT/PATCH занятие не конфликтовало само с собой.
Проверка вызывается в `create`, `replace` и `update`.

## В каком месте приложение может упасть и как это обработано?
Невалидные данные → validateLesson.js → 400
Битый JSON → errorHandler (entity.parse.failed) → 400
Запись не найдена → HttpError(404)
Пересечение занятий → HttpError(400)
Несуществующий маршрут → notFound.js → 404
Непредвиденная ошибка → errorHandler → 500 (без деталей, лог в консоль)
